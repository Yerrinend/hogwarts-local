# Хроники Хогвартса — локальная RPG 1.3.1

Интерфейс по концепту: тёмные зелёные панели, золотые акценты, страница книги, архив, материалы мира и менеджер API-подключений.

## Скачать и начать

**Тестовая версия 1.3.1 beta.** [Windows-сборка и примечания к выпуску](https://github.com/Yerrinend/hogwarts-local/releases).

1. Скачайте `HogwartsLocal-Windows.zip` из Assets выпуска.
2. Распакуйте весь архив и откройте `HogwartsLocal/HogwartsLocal.exe`.
3. Выберите имя героя и подключение модели. Стартовый мир уже включён; GitHub для начала игры не нужен.

Каждый игрок начинает собственную историю. Личные сохранения автора в комплект не входят. Интерфейс доступен на русском, украинском и английском; язык новых глав выбирается отдельно. Русские исходные материалы сохраняются в оригинале.

## Статус beta

Работают локальные сохранения, архив, экспорт/импорт, ветвление истории, стартовый мир и подключения моделей. Вход через ChatGPT и создание главы проверялись в Windows. Автоматические проверки GitHub используют подставные ответы; полный цикл с реальным пользовательским токеном ещё требует проверки. Финальный визуальный осмотр исправления боковой панели 1.3.1 не завершён. Ошибки можно сообщать через [Issues](https://github.com/Yerrinend/hogwarts-local/issues), без ключей и файлов авторизации.

В версии 1.3.1 исправлено сжатие карточек левой панели. В 1.3 улучшены ширина текста, раскрытие характеристик, переход к выбору и панель моделей на узких экранах. Полный текст главы остаётся в сохранении.

## Запуск Windows

Готовая сборка: откройте `HogwartsLocal.exe`. Устанавливать Python не нужно. Интерфейс откроется в браузере по адресу http://127.0.0.1:8765. Не закрывайте процесс, пока идёт генерация.

Личный режим: переключатель слева либо `HogwartsLocal.exe --personal`. Режимы имеют одинаковый интерфейс и отдельные сохранения. Это одна локальная программа с двумя независимыми пространствами, а не два интернет-сайта. Приложение слушает только loopback, не публикуется в сети.

Для остановки: Настройки → «Завершить приложение». Закрытие вкладки само по себе сервер не останавливает. Повторный запуск EXE открывает уже запущенное приложение.

Из исходников: Python 3.10+ → `start.bat` или `python server.py`. Дополнительные библиотеки для работы не нужны. Готовая сборка содержит EXE-запускатель и переносимый Python в папке runtime. Распакуйте весь ZIP; не переносите один EXE отдельно. `python build_portable.py` пересобирает этот комплект на Windows с установленным Python и компилятором .NET Framework. `build-exe.bat` — альтернативная сборка одним файлом через PyInstaller, требующая загрузки зависимости.

## Что работает

- Отдельные личная и новая игры, имя героя, локальное сохранение в SQLite.
- Вход через ChatGPT: официальный OAuth для локальных приложений с открытым кодом, несколько отдельных аккаунтов, каталог моделей аккаунта, запросы через Responses API с использованием разрешённой подписки. Доступность определяется OpenAI и настройками аккаунта/рабочего пространства.
- Дополнительно генерация через OpenAI/xAI Chat Completions API, шесть вариантов действий от модели; свой текст выбора.
- Менеджер многих API-ключей с поиском, фильтрами, прокруткой и удалением. ID модели вводится из кабинета провайдера. Количество успешных запросов и возвращённых токенов учитывается в текущем сеансе; остаток квоты неизвестен. Несколько ключей не обязательно имеют отдельные квоты.
- API-ключи и GitHub-токены только в памяти процесса. После перезапуска их вводят заново. Сессии ChatGPT сохраняются отдельно, зашифрованные Windows DPAPI для текущего пользователя Windows. Пароли и cookies браузера не читаются. Автоматической ротации аккаунтов нет.
- Архив, поиск, ветка после выбранной главы с резервной копией прежней истории.
- Редактор материалов и краткого сохранения, импорт Markdown и глав, экспорт/импорт полного JSON.
- Пакет перехода в другой чат: правила, материалы, краткое сохранение и последние восемь глав. Все главы остаются в архиве; более ранние факты должны присутствовать в кратком сохранении. Не обещается безошибочная память модели.
- GitHub через персональный токен: подключение репозитория, создание приватного, явная загрузка Markdown, запись/восстановление `hogwarts-local/<режим>/save.json`. Никакой автоматической записи без действия игрока.

## Стартовая основа

`starter/game.json` содержит расширенную авторскую основу 1.2: 21 материал о мире, исходных персонажах, местах, магии, школьной жизни, игровых правилах, семи сюжетных годах и условных AU-арках. Основа подготовлена по снимку `Yerrinend/Hogwarts-RPG` `9db6dc6d0fef4d8913ebb8e30ef14dbc3d97cbe0`. Получены все 177 файлов, проверены Git blob SHA; смысловая адаптация опирается на основные файлы канона и планов. Полный архив личных сцен не включён. Источники и границы переноса — `starter/source_manifest.json`, подробности — `starter/REVIEW.md`.

Первая глава генерируется моделью; заранее написанных глав нет. Поступление в AU — примерно в 18 лет; герой с исходной датой рождения 09.09.1973 ещё семнадцатилетний до дня рождения в сентябре 1991. Точные возрастные/календарные противоречия отмечены, не исправлены выдуманным ретконом. Повествование по умолчанию неграфическое.

**Обновление старой установки:** распакуйте весь новый комплект, предварительно завершив старый процесс через Настройки. Существующие прохождения не переписываются обновлением. Для чистой игры на основе 1.2 переключитесь на «Новое прохождение» → «Репозиторий» → «Новая игра с обновлённым миром». Сначала создаётся резервная копия старой новой игры. Личное прохождение это действие не меняет. Для продолжения личной истории используйте свои актуальные материалы и сохранение.

Исходные свойства мира и характеров отделены от последствий личных выборов. Романтические и другие зависящие от отношений арки имеют условия; они не создают готовой пары и не выбирают поступки нового игрока. Семь сюжетных лет — план ведущего, не семь заранее сгенерированных книг и не гарантия безошибочности модели. GM-файлы открываются с предупреждением о спойлерах. Для личной игры импортируйте актуальные материалы, главы и заполните краткое сохранение.

## Языки и русские файлы

Переключатель вверху меняет интерфейс: русский, украинский, английский. Настройки → «Язык новых глав» независимо задают язык будущей генерации; эта же настройка есть перед началом игры. Уже написанные главы, действия игрока, имена файлов и исходные тексты не переводятся и не переписываются. Оригинальная история остаётся на своём языке. Модель получает отдельное требование читать русские материалы и писать новые сцены на выбранном языке.

GitHub: «Загрузить .md» открывает выбор файлов с поиском и чекбоксами; поддерживаются Markdown, TXT и JSON. Пути с кириллицей и вложенные папки сохраняются. UTF-8/BOM и Windows-1251 распознаются при чтении. Запись прогресса всегда создаёт отдельный UTF-8 `save.json`, исходники репозитория не перекодируются. Для новой игры не выбирайте личные журналы и текущие сохранения.

Материалы хранятся полностью, но для запроса действует бюджет контекста. В него входят память, последние восемь глав и релевантные разделы файлов с приоритетом правил. В пакете явно перечислены полные, частичные и не включённые источники; это не заявление, что модель прочитала весь репозиторий. Для более точного поиска указывайте персонажа, место или задачу в своём действии.

## Вход через ChatGPT

1. Нажмите **Continue with ChatGPT** в правой панели. В окне пояснения нажмите эту кнопку повторно.
2. Завершите вход в системном браузере на `auth.openai.com`. Пароль вводится только на официальном сайте. Выберите аккаунт/рабочее пространство и предоставьте разрешение на использование подписки.
3. Вернитесь в приложение после сообщения о завершении входа. Выберите модель из каталога, полученного для этого аккаунта.
4. Другой аккаунт добавляется той же кнопкой. Существующие аккаунты выбираются нажатием на карточку. Для восстановления сессии — «Повторить вход», для отзыва — «Выйти».

**Оплата и лимиты:** подключение подписки не даёт безлимитного доступа. Разрешение использования дополнительных ChatGPT-кредитов регулируется настройками ChatGPT, а не нашим приложением. Если нужно работать только в рамках включённого объёма, отключите использование дополнительных кредитов для приложения в https://chatgpt.com/settings/usage. Не обещается, что любой аккаунт или любая модель поддерживается. При ошибке лимита генерация останавливается; на платный API приложение не переключается. Остаток сообщений не придумывается: доступна ссылка на Usage и счётчик выполненных запросов/токенов.

Контекст игры передаётся из локального сохранения. Вход через ChatGPT сам по себе не открывает приложению прежние беседы и память ChatGPT. Разные аккаунты получают один и тот же игровой контекст выбранного прохождения.

Хранилище `chatgpt-accounts.dpapi` находится в папке данных, отдельно от SQLite. Его нельзя переносить между пользователями Windows. В GitHub, экспорт JSON и пакет перехода оно не включается. Host-ID установки сохраняется до первого входа, client-ID и credentials разделены по регистрации. Авторизация использует PKCE, state и nonce; ID token проверяется по подписи RS256 через Windows CNG и ключам OpenAI, а также по issuer, audience, сроку и identity. Refresh-токены обновляются последовательно, изменения хранилища записываются атомарно. Выход сохраняет регистрацию и удаляет локальные токены; если удалённый отзыв не подтверждён, приложение сообщает об этом.

Интеграция следует https://developers.openai.com/siwc/token-sharing-open-source . Запросы отправляются только на публичный Responses endpoint с `store:false`, `stream:true`; ошибка и оборванный поток не превращаются в сохранённую главу. Реальный вход и генерацию через конкретную подписку необходимо проверить пользователю: среда сборки блокирует сетевые соединения, включая loopback. Автотесты проверяют протокол на подставных ответах, а Windows DPAPI и RSA-проверку — реальными системными функциями.

## Grok

Grok в этой версии подключается через **отдельно оплачиваемый API**. Его обычная подписка не переносится через API-ключ. Вход обычным аккаунтом Grok в приложение не реализован. Для использования своей подписки откройте https://grok.com, подготовьте пакет перехода в приложении, перенесите контекст в чат Grok, а полученный текст верните через «Вставить главу». Это пояснение отображается и в самом интерфейсе.

Модель возвращает структурированный JSON с текстом, вариантами и обновлённой памятью. Если формат некорректен, приложение показывает сырой ответ для проверки и ручного импорта; история не перезаписывается. Ошибка после отправки запроса может всё же означать списание у провайдера; автоматического повтора нет. Четыре таблицы и соблюдение канона задаются инструкцией; автоматического доказательства сюжетной непротиворечивости нет. Новые факты отражаются в кратком сохранении, а файлы хронологии редактируются вручную.

## GitHub

Для существующего репозитория создайте fine-grained personal access token с доступом Contents: read/write к выбранному репозиторию. Для создания репозитория нужен токен с соответствующими правами; существующий токен, ограниченный одним репозиторием, может не подойти. Вход OAuth/GitHub App в этой версии не реализован.

Загрузка читает выбранные текстовые файлы из одного снимка Git tree, по неизменяемому blob SHA. Одноимённые локальные материалы обновляются только после выбора. Скрытые пути исключены. Лимиты: 5000 локальных материалов, 2 миллиона символов на файл, суммарно 16 миллионов символов; одна загрузка GitHub до 16 МБ исходных байт. Бюджет запроса — 180 000 символов с явными отметками покрытия источников. Проверяйте состав выбранных файлов.

## Сохранения и распространение

В EXE-версии данные: `%LOCALAPPDATA%\HogwartsLocal`. В исходниках: `data/` рядом с `server.py` (можно изменить через `RPG_DATA_DIR`). Резервные копии перед импортом и ветвлением остаются там же; вернуть их можно через импорт JSON. Регулярно делайте экспорт.

Распространяйте EXE или исходники без `data/`, токенов и личных материалов. Сборка включает только интерфейс и стартовую основу, не локальные сохранения. Для обновления остановите приложение и замените всю папку программы новой сборкой, включая app и runtime; сохранения останутся в профиле пользователя. Перед обновлением сделайте экспорт JSON. Разные локальные режимы не являются защитой от владельца компьютера.

EXE не подписан цифровым сертификатом. Windows может показать SmartScreen. Не распространяйте сборку как подписанную или проверенную антивирусом.

## Проверка

`python -m unittest discover -s tests -v`

Проверка переводов без браузера: `node tests/test_i18n.js`. Проверяет переключение RU → EN → UK → RU и сохранность исходного текста/черновика; это не визуальная проверка в браузере.

Проверка отображения главы: `node tests/test_view.js` — повтор номера в заголовке, сохранность четырёх таблиц и отсутствие сворачивания обычной сцены без заголовка характеристик.

Используются подставные ответы API: реальные платные запросы и запись в GitHub требуют ключей пользователя и не выполняются тестами.
